Microservices:
Service Registry:
Database used to keep track of the available instances of each microservice in an application. Centralized and maintains/have details about all the Microservices (Status,Port,URL).
Connect with Microservice name
Dependency: Spring Cloud Netflix Eureka Server
Annotation: @EnableEurekaServer
Application Config Changes:
spring.application.name=EurekaServerName
server.port=5555
eureka.client.fetch-registry=false
eureka.client.register-with-eureka=false

Service Discovery Client:
Dependency: Spring Cloud Starter Netflix Eureka Client
Annotation: @EnableEurekaClient
Application Config Changes:
spring.application.name=ClientMSName
server.port=8181
eureka.client.service-url.defaultZone=http://localhost:5555/eureka 
eureka.instance.hostname=localhost

Feign Client: Declarative HTTP Framework used for implementig Rest Clients
Dependency: Spring Cloud Starter Openfeign, Eureka Client
Annotation: @EnableFeignClients, @FeignClient
Feign Client Interface Class: @FeignClient(value = <"Microservice Name as per Eureka">, url = ConstantUtils.BOOK_REST_URL)
and you can use multiple annotations with respect to your Microservice and create a method present in connecting Microservice.
Implement the interface by autowiring the FeignClient class and create a request mapping.

To Run Multiple Instance:
server.port=0
eureka.instance.instance-id=${spring.application.name}:${spring.application.instance_id:${random.value}} in the config while creating instance

Circuit Breaker : Identify the Microservices not running or down and kick start a fallback method to inform other services that the particular microservices is not working
Dependency: Hystrix Circuit Breaker
Annotation: @EnableHysrix
Write an fallback method in controller class with a requestmapping 
Application Config Changes:
spring.cloud.gateway.routes[0].filters[0]=name=CircuitBreaker
spring.cloud.gateway.routes[0].filters[0]=fallbackuri: forward:/userServiceFallBack
hystrix.command.default.circuitBreaker.requestVolumeThreshold=4
hystrix.command.default.metrics.rollingStats.timeInMilliseconds=10000
hystrix.command.default.circuitBreaker.errorThresholdPercentage=30
hystrix.command.default.circuitBreaker.sleepWindowInMilliseconds=30000

OAuth2.0:
Open Authorization. Design to allow a website or application to access the resources hosted by other applications on behalf of an user.

Resource Owner: 
User/System that owns the protected resources and can grant access to them.

Client:
System that requires access to the protected resources. It need Access token to access the protected resources.

Authorization Server:
Server recieves requests from client for Access tokens and issuses then after authentication with the owner.

Resource Owner:
Server that protects the user resources and recieve Access request from client. It accepts and validates the Accesstoken and return appropriate resouses to it.

Scopes: Specify exactly the reason for which access to resources may be granted. (Like Admin and User)
